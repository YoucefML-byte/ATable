# Usages autorisés de la clé secrète Supabase

La clé secrète (`SUPABASE_SECRET_KEY`, rôle `service_role`) **contourne la RLS**. Elle n'est utilisée que
là où la base ne peut pas exprimer la règle elle-même. La règle ESLint `no-restricted-imports`
(`eslint.config.mjs`) refuse l'import de `src/server/supabase/admin.ts` partout ailleurs. Tout nouvel usage
demande un ADR et une mise à jour de cette liste **et** de la liste d'ESLint.

| Fichier                             | Usage                                                                                                              | Pourquoi la RLS ne suffit pas                                                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `src/server/supabase/admin.ts`      | Création du client                                                                                                 | —                                                                                                                                    |
| `src/server/media/images.ts`        | Écriture des images dans le bucket `shop-media`                                                                    | Le stockage n'accepte que des fichiers ré-encodés par le serveur (vol. 03 §8) ; aucun utilisateur n'a le droit d'écrire directement. |
| `src/server/staff/device.ts`        | Lecture de l'appareil par l'empreinte de son cookie, liste des tuiles de l'équipe                                  | L'écran PIN est affiché **avant** toute connexion (aucun JWT).                                                                       |
| `src/app/api/staff/login/route.ts`  | Vérification du PIN (Argon2), compteurs d'échecs, création de la session Auth de l'employé, ligne `staff_sessions` | Le PIN et les compteurs ne sont jamais lisibles par un utilisateur (ADR-011).                                                        |
| `src/app/api/staff/logout/route.ts` | Révocation de la session employé                                                                                   | Idem.                                                                                                                                |
| `src/app/int-pro/equipe/page.tsx`   | Écran PIN : tuiles de l'appareil                                                                                   | Page publique de l'appareil enrôlé, sans session.                                                                                    |
| `src/features/staff/actions.ts`     | Création du compte Auth technique d'un employé, hachage du PIN                                                     | `auth.users` et `pin_hash` ne sont pas accessibles via la RLS. Le rôle patron est vérifié avant.                                     |
| `src/features/theming/actions.ts`   | Écriture de `logo_path` / `cover_path`                                                                             | Colonnes réservées au serveur (privilèges de colonnes) : le chemin vient du traitement d'image.                                      |
| `src/features/console/actions.ts`   | Invitation d'un patron, rattachement `shop_members`, réinitialisation 2FA, journal des actions de la plateforme    | Opérations sur `auth.users` ; le rôle administrateur de plateforme (aal2) est vérifié avant.                                         |
| `src/features/console/queries.ts`   | E-mail et dernière connexion des patrons dans la console                                                           | Ces informations n'existent que dans `auth.users`.                                                                                   |
| `scripts/create-platform-admin.ts`  | Création d'un administrateur de plateforme                                                                         | Script lancé à la main par le porteur de projet, jamais déployé.                                                                     |
